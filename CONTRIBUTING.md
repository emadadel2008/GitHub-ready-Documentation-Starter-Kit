# Contributing

## Documentation Principles

1. Prefer evidence over assumptions.
2. Never commit secrets.
3. Keep diagrams synchronized with implementation.
4. Record important architecture decisions.
5. Update documentation when behavior changes.
6. Mark unknown information explicitly.

## Pull Request Checklist

- [ ] Documentation updated
- [ ] Links tested
- [ ] Examples validated
- [ ] No secrets included
- [ ] Assumptions marked
- [ ] Unknowns recorded
