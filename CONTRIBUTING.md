# Contributing

## Documentation Principles

1. Prefer evidence over assumptions.
2. Never commit secrets.
3. Keep diagrams synchronized with implementation.
4. Record important architecture decisions.
5. Update documentation in the same change as the behavior, infrastructure, or operating procedure it describes.
6. Mark unknown information explicitly.
7. Give every maintained artifact an owner and a review date or cadence.
8. Keep the canonical copy in a discoverable, version-controlled location; link to supporting sources rather than creating competing copies.

## Pull Request Checklist

- [ ] Relevant documentation and diagrams updated with the implementation
- [ ] Important decisions and their rationale recorded
- [ ] Owner and review date/cadence are clear
- [ ] Links tested
- [ ] Examples validated
- [ ] No secrets included
- [ ] Assumptions marked with a validation path
- [ ] Unknowns recorded
